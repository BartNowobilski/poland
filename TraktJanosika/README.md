# Trakt Janosika — website

Marketing website for **Trakt Janosika**, eight Highlander-style homes in
Białka Tatrzańska (Podhale). Polish is the primary language, English secondary.

**Stack:** React 19 · Vite 7 · React Router 7 · plain CSS (design tokens) ·
`sharp` for image processing (dev only). Pages are prerendered to static HTML
at build time and hydrated in the browser. Hosted on Vercel.

---

## Quick start

```bash
npm ci            # install
npm run dev       # dev server → http://localhost:5173  (design reference: /styleguide)
npm run build     # production build + prerender → dist/
npm run preview   # serve dist/ locally
npm run lint      # ESLint
npm run images    # process photos (see "Images")
npm run brand     # regenerate favicons, share image and logo files (rarely needed)
```

Requires Node 20+.

## Common tasks

### Change a text

Edit `src/i18n/pl.js` **and** `src/i18n/en.js` (same key in both). In
development a console warning lists any keys missing from one language.
Text between `*asterisks*` in headings is shown in the italic accent colour.
Lines marked `// DRAFT` are new copy written for the redesign and should be
reviewed.

### Contact details, phone, data controller

`src/content/site.js`. While `phone` is `null` it is hidden everywhere.
`dataController` is used in the privacy notice under the contact form — until
it is filled in, the notice shows a visible placeholder.

### Add or replace photos

See **[photos/README.md](photos/README.md)**. In short:

1. drop files into `photos/<category>/` (architecture, interiors, surroundings,
   lifestyle, construction, renderings);
2. run `npm run images`;
3. optionally give them alt text / order / `featured` in `src/content/gallery.js`.

New photos appear in the gallery automatically. The pipeline creates AVIF
images at 640/1280/1920/2560 px plus a JPEG fallback, a blurred placeholder,
and a content hash for caching. Only new or changed files are processed.

To use a different photo in a homepage section, change its id in
`src/content/images.js`.

### Fill in a house

Edit `src/content/residences.js`, e.g.:

```js
export const RESIDENCES = [1, 2, 3, 4, 5, 6, 7, 8].map(blank);

Object.assign(RESIDENCES[0], {
  status: "available",            // "available" | "reserved" | "sold"
  floorArea: 182.5,               // m²
  plotArea: 812,                  // m²
  bedrooms: 5,
  bathrooms: 4,
  cover: "architecture-dom-1",    // image id
  gallery: ["architecture-dom-1", "interiors-dom-1-salon"],
  floorPlans: [{ image: "renderings-dom-1-parter", label: { pl: "Parter", en: "Ground floor" } }],
  specs: [{ label: { pl: "Garaż", en: "Garage" }, value: { pl: "1 stanowisko", en: "1 space" } }],
  note: { pl: "…", en: "…" },
});
```

Empty values show “—”. A house gets a **Szczegóły / Details** dialog as soon as
it has a gallery, plans, specs or a note. Only enter verified data. House names
are placeholders (“Dom 1–8”) — change `label` once official names exist.

### Add a construction update

1. Put photos in `photos/construction/<yyyy-mm>/`, run `npm run images`.
2. Add an entry to `src/content/progress.js` (a commented example is in the file):

```js
{
  id: "2026-03-fundamenty",
  date: "2026-03",                 // or "2026-03-14"
  milestone: true,
  title: { pl: "Fundamenty", en: "Foundations" },
  text: { pl: "…", en: "…" },
  photos: ["construction-2026-03-fundamenty-01", "construction-2026-03-fundamenty-02"],
}
```

Newest entries are shown first; photos also appear in the gallery under
“Postęp budowy”.

### Nearby places / distances

`src/content/location.js`. Distances come from the original site copy — change
them only with verified figures (the long location text in `i18n` mentions
them too).

## SEO & sharing

- Static `<head>` (title, description, Open Graph, structured data) is in
  `index.html`; per-page titles/descriptions come from `meta` in the i18n files
  and are written into each prerendered page.
- Share image: `public/og/trakt-janosika.jpg` (`npm run brand` rebuilds it).
- `public/sitemap.xml` and `public/robots.txt` — update `lastmod` / add new
  pages to the sitemap when adding routes.
- Structured data (JSON-LD) contains only facts published on the site.
- Pages are prerendered in Polish; English is selected via the PL/EN switch
  (remembered) or `?lang=en`.

## Build & deployment

`npm run build` runs three steps: the Vite client build, an SSR build of
`src/entry-server.jsx`, and `scripts/prerender.mjs`. The last step writes:

| URL | file |
| --- | --- |
| `/` | `dist/index.html` |
| `/gallery` | `dist/gallery.html` (via `cleanUrls`) |
| unknown URLs | `dist/404.html` (real 404 status) |

`vercel.json` configures clean URLs, long-term caching for hashed assets,
fonts and versioned images, and security headers.

**Workflow:** work on a branch and check the Vercel preview before merging to
`main`. Production deploys from `main` — merge only when approved.

## Performance notes

- Hero image: separate portrait crop for phones (`bialka-portrait`), preloaded
  per screen shape. The preload is injected at build time in `vite.config.js`.
- CSS is inlined into each page. Fonts are self-hosted. The Polish
  diacritics ship as tiny subsets (`*-polish*.woff2`), with metric-matched
  fallbacks to avoid layout shift.
- Below-the-fold images lazy-load. The lightbox mounts only 3 images at a
  time. The gallery shows 24 per page. The 360° viewer and Google Maps load
  only when needed.
- Motion respects `prefers-reduced-motion`.

Lighthouse (local production build, mobile with real 4G/CPU throttling): home
100/100/100/100; gallery ≈ 89/100/100/100. Desktop 100 across the board.
